# Phase 9: Express 5 Upgrade

## Why

The project is running Express 4.18.1. Express 5 is the latest major version with improved performance, better TypeScript types, and modern JavaScript features. Upgrading keeps the project current and benefits from performance improvements.

## What Changes

### Dependencies Updated

| Package | Current | Target | Risk |
|---------|---------|--------|------|
| `express` | 4.18.1 | 5.2.1 | Low (simple API usage) |

### Files Modified

| File | Changes |
|------|---------|
| `package.json` | Update express version |
| `package-lock.json` | Auto-generated by npm install |
| `openspec/config.yaml` | Mark Phase 9 as completed |

### Express 5 Breaking Changes Assessment

```
┌──────────────────────────────────────────────────────────────────┐
│ Express 4 → 5 Breaking Changes Analysis                           │
├────────────────────────┬────────┬────────────────────────────────┤
│ Change                  │ Impact │ Why                             │
├────────────────────────┼────────┼────────────────────────────────┤
│ express.json() removed │ LOW     │ We use it explicitly, not as    │
│                         │         │ bundled middleware              │
├────────────────────────┼────────┼────────────────────────────────┤
│ Query string parsing   │ NO      │ We don't use query params       │
├────────────────────────┼────────┼────────────────────────────────┤
│ Error handler signature│ NO      │ No custom error handlers        │
├────────────────────────┼────────┼────────────────────────────────┤
│ res.json() null values │ LOW     │ We don't pass null/undefined    │
│                         │         │ to res.json()                   │
├────────────────────────┼────────┼────────────────────────────────┤
│ req.params type        │ LOW     │ We destructure as strings       │
├────────────────────────┼────────┼────────────────────────────────┤
│ app.listen() callback  │ NO      │ Not using callback form         │
└────────────────────────┴────────┴────────────────────────────────┘
```

### Current Express Usage

```
src/main/api.js (7 routes)
├── GET  /api/blocks           → return chain
├── GET  /api/blocks/length    → return chain length
├── GET  /api/blocks/:id       → return paginated blocks
├── GET  /api/mine-transactions→ mine and redirect
├── POST /api/transact         → create transaction
├── GET  /api/transaction-pool-map → return pool map
├── GET  /api/wallet-info      → return wallet info
└── Middleware: express.json(), express.static(), cors()
```

## Scope

**In scope**:
- Update express to 5.2.1 in package.json
- Run npm install
- Run npm test to verify no regressions
- Run npm start to verify app launches and API endpoints work
- Update openspec/config.yaml

**Out of scope**:
- Adding new API endpoints
- Refactoring API code
- Adding authentication or middleware
- TypeScript migration

## Success Criteria

1. `npm install` completes without errors
2. `npm test` passes (same results as Phase 8: 4/7 suites, 108/112 tests)
3. `npm start` launches the app correctly
4. All 7 API endpoints respond correctly
5. No new deprecation warnings in console

## Risks

- **Low risk overall** — codebase uses only basic Express patterns
- **Potential issue**: `express.json()` may need separate installation if removed from core
- **Potential issue**: `res.redirect()` behavior may have changed slightly
- **Mitigation**: Test all endpoints after upgrade

## Migration Steps

1. Update package.json with express 5.2.1
2. Run `npm install` to update lock file
3. Run `npm test` to verify no regressions
4. Run `npm start` to verify app launches
5. Test API endpoints manually or via curl
6. Update openspec/config.yaml to mark Phase 9 complete
